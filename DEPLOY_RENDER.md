# Deploying the Gradio Application to Render (Free Web Service)

This guide provides step-by-step instructions for deploying your trained XGBoost model and Gradio web interface to **Render's Free Web Service tier**.

---

## Why Render?

Render provides a free cloud hosting tier for web services that:
- Natively supports Python web applications.
- Dynamically assigns an external port via the `PORT` environment variable (default: `10000`).
- Does **not** require credit card payments or paid tier upgrades.
- Serves your application on a permanent public HTTPS URL (e.g. `https://your-app-name.onrender.com`).

---

## 1. Project Files Required for Deployment

The deployment package is completely self-contained. It relies on the pre-trained [`model.pkl`](file:///d:/MLFlow/model.pkl) and does **not** need the local MLflow tracking server or `mlruns/` directory at runtime.

### Files to Include in Your Git Repository
- [`app.py`](file:///d:/MLFlow/app.py) (Main Gradio application, configured with host `0.0.0.0` and `PORT`)
- [`model.pkl`](file:///d:/MLFlow/model.pkl) (Serialized model artifact generated by `export_model.py`)
- [`requirements.txt`](file:///d:/MLFlow/requirements.txt) (Python dependencies)
- [`.gitignore`](file:///d:/MLFlow/.gitignore) (Ensures local environments and caches are not uploaded)
- [`README.md`](file:///d:/MLFlow/README.md) *(Optional, recommended)*

### Files to EXCLUDE (handled automatically by `.gitignore`)
- `auth/` (Local virtual environment — Render builds its own Linux environment)
- `mlruns/` (Local MLflow tracking directory)
- `__pycache__/` and `.pytest_cache/` (Local cache files)
- `.env` (Any environment secrets)

## 2. Step 1: Create a GitHub Repository

1. Go to [github.com](https://github.com/) and log in to your account.
2. In the upper-right corner, click **+** $\rightarrow$ **New repository**.
3. **Repository name**: Enter a name, such as `xgboost-mlflow-app`.
4. **Visibility**: Select **Public** (or Private, if you connect your GitHub account to Render with private repo permissions).
5. Do **not** initialize with a README, .gitignore, or license (you already have them locally).
6. Click **Create repository**.

---

## 3. Step 2: Push Your Local Code to GitHub

Open PowerShell in `D:\MLFlow` and run:

```powershell
# Initialize git if not already initialized
git init

# Stage the tracked files
git add app.py model.pkl requirements.txt .gitignore README.md

# Verify which files are staged (make sure auth/ and mlruns/ are NOT staged)
git status

# Commit the files
git commit -m "Initial commit: Gradio app and trained model for Render deployment"

# Set branch to main
git branch -M main

# Add your GitHub repository as remote (replace with your actual GitHub URL)
git remote add origin https://github.com/<YOUR_GITHUB_USERNAME>/xgboost-mlflow-app.git

# Push to GitHub
git push -u origin main
```

*(Alternatively, you can drag and drop `app.py`, `model.pkl`, `requirements.txt`, and `.gitignore` directly into the GitHub web interface using **Upload files**).*

---

## 4. Step 3: Create a Free Web Service on Render

1. Go to [render.com](https://render.com/) and click **Sign In** (sign in using your GitHub account for easiest integration).
2. From the Render Dashboard, click the blue **New +** button in the top right.
3. Select **Web Service**.
4. Choose **Build and deploy from a Git repository** $\rightarrow$ Click **Next**.
5. Connect your GitHub account (if not already connected) and select your repository (`xgboost-mlflow-app`).

---

## 5. Step 4: Configure Web Service Settings

Configure the deployment form with the following exact settings:

| Setting Field | Value | Notes |
| :--- | :--- | :--- |
| **Name** | `xgboost-mlflow-predictor` *(or any unique name)* | Becomes part of your public URL: `https://<name>.onrender.com` |
| **Region** | Choose the closest region (e.g. *Oregon (US West)* or *Frankfurt (EU)*) | Any region works |
| **Branch** | `main` | Default repository branch |
| **Root Directory** | *(Leave blank)* | Uses root of repository |
| **Runtime** | `Python 3` | Built-in Python environment |
| **Build Command** | `pip install -r requirements.txt` | Installs project dependencies |
| **Start Command** | `python app.py` | Launches Gradio on host `0.0.0.0` and Render's `PORT` |
| **Instance Type** | **Free** ($0/month) | 0.1 CPU, 512 MB RAM |

### Environment Variables (Optional)
Under the **Environment Variables** section, you may optionally add:
- Key: `PYTHON_VERSION`
- Value: `3.11.9`

*(Render automatically injects the `PORT` environment variable; `app.py` reads it dynamically).*

---

## 6. Step 5: Deploy and Monitor Build Logs

1. Scroll to the bottom and click **Create Web Service** (or **Deploy Web Service**).
2. Render will trigger an automated build:
   - It clones your repository.
   - Runs `pip install -r requirements.txt`.
   - Starts `python app.py`.
3. In the live log console, you will see output similar to:
   ```text
   ==> Running build command 'pip install -r requirements.txt'...
   Successfully installed gradio pandas xgboost scikit-learn joblib...
   ==> Uploading build...
   ==> Build successful 🎉
   ==> Deploying...
   ==> Starting service with 'python app.py'...
   * Running on local URL: http://0.0.0.0:10000
   ==> Your service is live 🎉
   ```
4. Within 2–3 minutes, the status indicator in the top-left will change from **In progress** to **Live**.

---

## 7. Step 6: Test the Public Application URL

1. At the top-left of the Render dashboard, copy your public service URL:
   `https://xgboost-mlflow-predictor.onrender.com`
2. Open the URL in any web browser (or on your phone).
3. The **XGBoost Model Prediction** interface will load:
   - Enter **Feature 1** (e.g. `3.0`) and **Feature 2** (e.g. `13.0`).
   - Click **Predict**.
   - Confirm that the predicted class and confidence are displayed correctly.
   - Click on the provided preset examples (`[2.0, 12.0]`, `[7.0, 17.0]`, etc.) to verify responsiveness.
4. Copy and submit this public URL for your academic submission!

---

## 8. Important Notes on Render's Free Tier

> [!NOTE]
> **Free Tier Sleep Behavior (Spindown)**:
> Render's Free web services spin down (go to sleep) after **15 minutes of inactivity** to conserve cloud resources.
> When a new request arrives after inactivity:
> - The application takes approximately **30 to 50 seconds** to wake up (cold start).
> - Once awake, the application responds instantly.
> - This is normal behavior on free cloud tiers.
